# Лавка шамана — Telegram Mini App

Готовый каркас интернет-магазина внутри Telegram для `@ShamanLavkaBot`.

## Что уже реализовано

- Telegram Mini App frontend без отдельной сборки Node.js.
- Серверная проверка `Telegram.WebApp.initData` по HMAC.
- Автосоздание пользователей Telegram.
- Администратор: первый **верифицированный** вход пользователя `@shamanchik007` закрепляет его numeric Telegram ID как admin в базе.
- Категории и товары полностью редактируются через встроенную админку.
- Корзина, остатки, оформление заказа, применение внутреннего баланса.
- Реферальная система:
  - учитываются только приглашённые, совершившие хотя бы одну оплаченную покупку;
  - 1 активный приглашённый = 1%, 2 = 2%, ... 10 и больше = 10%;
  - текущая ставка начисляется на внутренний баланс пригласившего с каждой оплаченной покупки его приглашённых;
  - база начисления — товары после списания внутреннего баланса, без стоимости доставки;
  - первая покупка приглашённого сразу активирует его и участвует в начислении новой ставки.
- CDEK API v2: OAuth, поиск города, ПВЗ, расчёт списка тарифов.
- Платёжный слой: mock для локальной проверки и YooKassa для продакшна.
- Webhook YooKassa перепроверяет статус платежа через API перед пометкой заказа как paid.
- Telegram-бот `/start`, реферальные ссылки и кнопка открытия Mini App.
- Docker Compose: FastAPI + bot + PostgreSQL.

## Быстрый локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
cp .env.example .env
python scripts/seed.py
uvicorn app.main:app --reload
```

Откройте `http://localhost:8000`. В dev-режиме используется тестовая Telegram-авторизация. Для проверки покупателя можно в DevTools изменить `DEV_USER` в `static/app.js` или запускать через Telegram после публикации HTTPS.

## Продакшн через Docker

1. Купите любой VPS с Docker (Ubuntu 24.04 достаточно для старта).
2. Скопируйте проект.
3. `cp .env.example .env`.
4. Заполните `BOT_TOKEN`, `APP_URL=https://ваш-домен`, CDEK и платёжные ключи.
5. Для YooKassa: `PAYMENT_PROVIDER=yookassa`.
6. `docker compose up -d --build`.
7. Поставьте HTTPS reverse proxy (Caddy/Nginx) на порт 8000.
8. В кабинете YooKassa укажите webhook: `https://ваш-домен/api/payments/yookassa/webhook`.
9. Запустите `python scripts/seed.py` внутри api-контейнера или создайте категории через админку.

## CDEK

Исходный город уже указан: **Октябрьский, Республика Башкортостан**. В `.env` нужны только `CDEK_CLIENT_ID` и `CDEK_CLIENT_SECRET`.

Для создания реальной накладной CDEK нужны дополнительные реквизиты отправителя/получателя и выбранный тариф. Текущая версия уже рассчитывает варианты доставки и ПВЗ, но автоматическое создание накладной оставлено за админским подтверждением, чтобы заказ не улетал в CDEK до оплаты и проверки данных.

## Оплата

Так как в переписке название было передано как `UKSSD`, проект сделан с заменяемым платёжным адаптером. В комплекте есть **YooKassa**, потому что она соответствует описанному сценарию оплаты по API. Если у вас другой эквайринг, достаточно добавить новый gateway в `app/services/payments.py` — каталог, заказы и рефералка не меняются.

## Безопасность перед публикацией

- `DEV_AUTH=false`.
- Никогда не храните `BOT_TOKEN`, CDEK и платёжные секреты в Git.
- После первого входа администратора проверьте, что его numeric Telegram ID закрепился в БД.
- Сделайте резервные копии PostgreSQL.
- Для товаров, продажа которых регулируется законом или правилами платёжного провайдера/площадки, самостоятельно настройте допустимый ассортимент, возрастные предупреждения и условия продажи.
