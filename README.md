# Лавка шамана

Интернет-магазин внутри Telegram: каталог товаров, корзина, доставка СДЭК, оплата через ЮKassa и личный кабинет с реферальным балансом. Управление товарами и заказами встроено в то же приложение.

**Сайт:** [lavkashamana.ru](https://lavkashamana.ru/) · **Telegram:** [@ShamanLavkaBot](https://t.me/ShamanLavkaBot)

Репозиторий содержит исходники, перенесённые с рабочего сервера, изображения магазина, конфигурацию развёртывания и архив предыдущих версий. Пользователи, заказы, настройки магазина и каталог из производственной БД в Git не входят. Подробности переноса — в [docs/server-import.md](docs/server-import.md).

## Возможности

- Каталог с категориями, фотографиями, ценами, описаниями и остатками товаров.
- Корзина, оформление заказа, история заказов и сохранение контактных данных и адреса доставки.
- Вход через Telegram Mini App с проверкой подписи `initData` на сервере.
- СДЭК: поиск городов и ПВЗ, расчёт тарифов, доставка в ПВЗ или курьером, попытка создания отправления после оплаты.
- ЮKassa: создание платежа, передача данных чека и проверка статуса платежа через API при обработке webhook. Для разработки есть mock-оплата.
- Реферальные ссылки, внутренний баланс и его использование при покупке.
- Админка: категории, товары, загрузка изображений, заказы и статусы, обзор продаж, настройки и информационные тексты магазина.
- Публичный раздел документов на продукцию из `static/document/`.

### Как устроена реферальная программа

Текущий серверный код начисляет **0,5 процентного пункта за каждого активного приглашённого**, максимум **10%**. Активным считается пользователь, у которого есть заказ в статусе `paid`. Первая оплаченная покупка уже участвует в расчёте новой ставки.

База начисления — стоимость товаров за вычетом использованного внутреннего баланса. Доставка исключена. Повторное начисление по одному заказу предотвращается уникальным ограничением в БД.

## Стек и структура

Python 3.12, FastAPI, SQLAlchemy 2, PostgreSQL 16, aiogram 3. Фронтенд — HTML, CSS и JavaScript без Node.js-сборки. Nginx завершает HTTPS и проксирует запросы к API; FastAPI также раздаёт статические файлы.

```text
app/
  main.py                 HTTP API, заказы, админка, webhook
  bot.py                  Telegram-бот: /start и кнопка Mini App
  config.py               Настройки из окружения и .env
  db.py, models.py         Подключение к БД и модели
  schemas.py              Схемы запросов
  services/               Telegram, СДЭК, платежи, рефералка
static/
  index.html              Страница приложения
  app-admin-v4.js          Скрипт, подключённый текущей страницей
  app-admin-v5.js, app.js  Другие версии, сохранённые с сервера
  uploads/                Изображения товаров
  document/               Публичные документы на продукцию
scripts/seed.py            Начальные категории
tests/test_referrals.py    Существующий тест реферальной логики
deploy/nginx/              Конфигурация домена с сервера
archive/                  Исторические копии исходников и материалов
docs/                     Описание и карта переноса
```

Файлы в `archive/` нужны для истории и сравнения. Они исключены из Docker-контекста и не обслуживаются как часть сайта.

## Локальный запуск

Нужен Python 3.12. Для разработки используется SQLite, действующие ключи Telegram и платёжных сервисов не обязательны.

```bash
git clone https://github.com/WizardJIOCb/lavkashamana.ru.git
cd lavkashamana.ru
python -m venv .venv
```

Активируйте окружение: `source .venv/bin/activate` в Linux/macOS или `.\.venv\Scripts\Activate.ps1` в PowerShell. Скопируйте `.env.example` в `.env` (`cp` в Bash, `Copy-Item` в PowerShell), затем:

```bash
python -m pip install -r requirements.txt
python scripts/seed.py
python -m uvicorn app.main:app --reload --host 127.0.0.1
```

Откройте [localhost:8000](http://localhost:8000/). Документация API доступна на `/docs`, схема — на `/openapi.json`.

В шаблоне включены `DEV_AUTH=true` и `PAYMENT_PROVIDER=mock`: браузер может использовать тестового пользователя без Telegram. Первый вход с настроенным `ADMIN_TELEGRAM_USERNAME`, пока в БД нет администратора, выдаёт ему права администратора. Поэтому для публичного сервера обязательно установить `DEV_AUTH=false` и использовать отдельную БД, без тестового администратора.

`seed.py` создаёт только четыре начальные категории, а не копию рабочего каталога. Товары можно добавить через админку.

## Настройки

Все переменные задаются в локальном `.env`; секреты не публикуются в Git.

| Переменные | Назначение |
| --- | --- |
| `APP_NAME`, `APP_ENV`, `APP_URL` | Название, метка окружения и публичный URL приложения; `APP_ENV` сам по себе не отключает dev-авторизацию |
| `DATABASE_URL` | SQLite при локальном запуске; в Compose переопределяется на PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для Compose; задайте случайную строку, например из букв и цифр, без специальных символов URL |
| `BOT_TOKEN`, `BOT_USERNAME` | Токен и имя Telegram-бота |
| `ADMIN_TELEGRAM_USERNAME` | Имя пользователя для первоначального назначения администратора |
| `DEV_AUTH` | `true` только для локальной разработки; `false` на публичном сервере |
| `PAYMENT_PROVIDER` | `mock` для разработки, `yookassa` для ЮKassa |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Доступ к магазину ЮKassa |
| `YOOKASSA_RETURN_URL` | URL возврата после оплаты |
| `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET`, `CDEK_API_BASE` | Доступ к API СДЭК |
| `CDEK_FROM_CITY`, `CDEK_FROM_REGION`, `CDEK_FROM_COUNTRY` | Местоположение отправителя |
| `CDEK_SHIPMENT_POINT` | Код пункта отправления для создания заказа СДЭК |
| `DEFAULT_PACKAGE_*`, `DEFAULT_PRODUCT_WEIGHT_G` | Резервные размеры и вес упаковки/товара |

При включённой интеграции СДЭК сервер повторно проверяет тариф при оформлении заказа. После оплаты пробует создать отправление и сохранить его UUID. Ошибка этой операции записывается в лог; сам заказ остаётся оплаченным. Это место нужно контролировать при эксплуатации.

## Docker Compose и сервер

1. Скопируйте `.env.example` в `.env`, задайте `POSTGRES_PASSWORD` и заполните интеграции.
2. Для Telegram установите `APP_URL=https://lavkashamana.ru`, `DEV_AUTH=false`, настоящий `BOT_TOKEN` и нужное имя администратора.
3. Для реальной оплаты установите `PAYMENT_PROVIDER=yookassa`, ключи ЮKassa и HTTPS URL возврата.
4. Запустите сервисы:

```bash
docker compose up -d --build
docker compose exec api python scripts/seed.py
docker compose ps
docker compose logs --tail=100 api bot db
```

Compose поднимает `db`, `api` и `bot`. Если нужен только локальный интерфейс без токена бота, используйте `docker compose up -d --build db api`. API слушает порт `8000`; PostgreSQL хранит данные в томе `pgdata`. `docker-compose.override.yml` сохраняет загруженные изображения в `./static/uploads` на хосте.

В [deploy/nginx/lavkashamana.ru.conf](deploy/nginx/lavkashamana.ru.conf) сохранена конфигурация домена. Она ссылается на сертификаты Certbot в `/etc/letsencrypt/`: на новом сервере их нужно выпустить отдельно перед использованием этой конфигурации. Вебхук ЮKassa: `https://lavkashamana.ru/api/payments/yookassa/webhook`.

Для установки за Nginx ограничьте доступ к порту `8000` локальным интерфейсом или межсетевым экраном. В перенесённом Compose сохранена исходная публикация `8000:8000`.

### Данные и резервное копирование

Для восстановления магазина нужны **БД PostgreSQL, `.env` и `static/uploads/`**; если менялись публичные документы — также `static/document/`. Git хранит код и перенесённые публичные файлы, но не является полной резервной копией магазина.

Экспорт БД на Linux-сервере:

```bash
docker compose exec -T db pg_dump -U shaman shaman > backup.sql
```

Храните дампы и `.env` отдельно от репозитория. `docker compose down -v` удаляет том с БД. Смена `POSTGRES_PASSWORD` в `.env` не меняет пароль уже созданного пользователя в существующем томе PostgreSQL.

## Проверки и известные ограничения снимка

```bash
python -m pytest tests -q
```

- Существующий тест рефералки ожидает старую ставку 1% за приглашённого, тогда как текущий код считает 0,5%. Тест сохранён как на сервере и падает на этом расхождении; его наличие не означает успешную проверку проекта.
- На момент обследования сервер возвращал HTTP 502: PostgreSQL был остановлен после перезагрузки, API перезапускался. У `db` в исходном Compose нет политики `restart`. Импорт в Git не восстанавливает сервисы и не меняет сервер.
- Таблицы создаются через `Base.metadata.create_all`; системы миграций схемы в проекте нет. Изменение моделей само по себе не обновляет существующие таблицы.
- Исторические README и статусы в `archive/` могут описывать устаревшее поведение. Текущая точка входа фронтенда использует `app-admin-v4.js`, несмотря на наличие файла `v5`.

Перенос не включает проверку реальных оплат, доставки и работы Telegram-бота с производственными ключами.
